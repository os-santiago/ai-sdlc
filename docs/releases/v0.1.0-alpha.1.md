# ai-sdlc v0.1.0-alpha.1

**Status:** alpha, for technical evaluation. It is not for production use.

## What this release does

For a GitHub repository you choose, ai-sdlc turns an authorized issue into a
pull request and merges it after these steps:

1. **Generation:** a model, used only as a service, writes the change in an
   offline sandbox.
2. **Verification:** the repository's own test suite runs offline in gVisor
   pods, on the base revision, on the base plus the new tests, and on the
   candidate. It must show a test that fails on the old code and passes on the
   new one.
3. **Review:** an independent read-only reviewer approves the change.
4. **Publication and merge:** the runtime opens the pull request and merges it
   only after the required checks pass.

You onboard a repository with a reviewed **project manifest**. It declares the
toolchain image, test command, allowed paths and merge floor, and needs no code
changes to ai-sdlc. See the [adoption guide](../adoption.md).

Evidence: [generic inner loop end-to-end run](../evidence/2026-11-21-generic-inner-loop-e2e.md).

## Known limits

- **Measured reliability:** one demonstrated run. The evaluation battery and
  its success rate are in progress (M4).
- **Generator workspace:** it has no build toolchain or network, so the agent
  cannot run the tests itself. Verification runs them afterwards.
- **Weak decisions:** without a JUnit report, verification compares exit codes
  and the reviewer judges whether the new test exercises the requested
  behaviour.
- **Dependencies:** they must be vendored or present in the toolchain image,
  because verification has no network.
- **Base branch:** `main` only. Repeat count 1–3, test timeout 30–600 s, and the
  workspace-bundle size limits apply.
- **Platforms:** kind on Linux amd64. OpenShift validation is in progress (M5).
- **Upgrades:** an existing installation cannot yet apply migration 0038. The
  upgrade tools refuse it (fail closed); install fresh for this release.
- **Model service:** validated with the local OpenAI-compatible simulator and the
  bundled Codex CLI. At installation, `--model-upstream` accepts only a plain
  HTTP endpoint on a literal private address without a credential, so a hosted
  HTTPS API that needs a token cannot yet be configured there.
- **Outer loop:** build, provenance and deployment remain specific to the
  reference project (v1.1).

## Security posture

Every stage runs as a separate component under its own signed authority, with
fail-closed stops and retained evidence. See the
[security overview](../security-overview.md) and [SECURITY.md](../../SECURITY.md).
